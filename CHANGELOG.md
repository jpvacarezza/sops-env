# Changelog

## Unreleased

## v0.2.1 — 2026-10-16

- `v0.2.0` was tagged without an annotation, so `git ls-remote … refs/tags/v0.2.0^{}`
  returns nothing and a consumer cannot verify its lockfile SHA against the tag.
  Pin `v0.2.1`, which is annotated.
- materialize accepts `.env.local` files written by a predecessor tool (first
  line `# Generated by `<anything>materialize` — do not edit.`) instead of
  refusing them.
- Install gate: `minimumReleaseAge` (3 days) and `trustPolicy: no-downgrade` in
  `pnpm-workspace.yaml`. Lockfile regenerated; vitest 4.1.12 became 4.1.11,
  which clears the floor.
- CI: a `security` job (`pnpm audit`, semgrep with in-repo rules pinned to
  1.179.0), a weekly `Dependency updates` issue, Dependabot for GitHub Actions
  only, a composite `setup-pnpm` action, `.nvmrc`, and cancellation of
  superseded PR runs. Release now checks that the tag is annotated, matches
  `package.json` and resolves to the checked-out commit.
- Commit hygiene: husky + lint-staged pre-commit, commitlint on commits and PR
  titles. Hooks install with `pnpm hooks:install`; there is no `prepare`
  script, because pnpm runs it for git dependencies.
- Docs: ADRs 0001-0004, `docs/superpowers/` spec and plan convention,
  `AGENTS.md`/`CLAUDE.md`, and `docs/verification.md` for before/after checks
  on behavior-changing PRs.

## v0.2.0 — 2026-10-16

- **Breaking:** requires `sops` >= 3.11.0. `set` now passes the value to
  `sops set --value-stdin`, so it is no longer on the child's argv (the v0.1.0
  known limitation is closed). CI pins sops 3.11.0.
- Specs for `run`, `edit` and `unset`, which had none.
- Coverage floors raised to lines 75 / functions 80 / branches 76 /
  statements 75 (measured 77.9 / 82.8 / 78.5 / 77.3).
- CI: Windows job (sops pinned by checksum), tarball contents check, and a tag
  workflow that publishes the CHANGELOG section as the GitHub release notes.
- `src/ui/shell.mjs` (1871 lines) is split into `shell-layout.mjs`,
  `shell-state.mjs` and `shell-render.mjs`; `shell.mjs` re-exports the same
  public names. No behaviour change.

## v0.1.0 — 2026-10-16

First release. Extracted from tripgency's `tools/secrets/` with history.

- Configuration moves to `secrets.config.mjs`: scopes with per-key notes, apps
  with scopes, dotenv/example/schema/destination, environments, pairs,
  exemptions, placeholder pattern, provider env-var names, contract roots.
- `loadConfig()` runs once in the bin; every command takes the frozen `ctx`.
- Destinations are providers (`vercel`, `railway` built in; inline or by path).
- Schema validation is optional: `schema-unchecked` when `tsx` or `schema` is
  absent; `runner: 'node'` for JS-only schemas. A configured `schema.file`
  that does not exist is `schema-missing`, an error.
- The names-only guard covers provider name fields, destination
  `project`/`service.*`, pair `name`/`why` and exemption reasons; a rejected
  string is never echoed. Platform error bodies are redacted and capped.
- `materialize` refuses a target git does not ignore, a file it did not
  generate, and a `dotenv` outside the config root.
- The `sync: false` environment is the laptop one, whatever its name.
- `import('sops-env').SecretsConfig` resolves through the `types` export.
- `list --json` rows carry `note`; the grid pane shows it.
- `declaresEncryptedKey(text, key)` exported for key-less CI gates.
- Vercel targets come from `providers.vercel.targets` (the
  `VERCEL_SYNC_TARGETS_*` environment override is gone).
- Command hints say `sops-env <cmd>`; messages name `secrets.config.mjs`.
- An unknown subcommand exits 2; a missing config exits 1.
- Coverage floors: lines 68 / functions 75 / branches 71 / statements 68
  (measured 74.58 / 81.51 / 76.91 / 74.15; the floors are unchanged).

### Known limitations

- `set` passes the value to the `sops set` child on its argv, visible to
  same-user processes for the child's lifetime: sops 3.9 has no stdin mode.
  It is never an argument to `sops-env` itself.
